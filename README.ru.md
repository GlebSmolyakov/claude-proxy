# claude-proxy

[English](README.md) · Русский

Агент правит файл, а вы видите дифф карточкой в редакторе и жмёте «разрешить». Правка ложится в буфер, где её видно и можно откатить, а не на диск в обход вас. Внутри работает обычный Claude Code: свой системный промпт, свои инструменты, `CLAUDE.md`, скиллы, сабагенты, ваши настройки и MCP-серверы. Снаружи он говорит с редактором по [Agent Client Protocol](https://agentclientprotocol.com), а движок — [Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-typescript).

> [!WARNING]
> Ходы оплачивает тариф, под которым залогинен местный Claude Code. Anthropic [не разрешает](https://code.claude.com/docs/en/agent-sdk/overview) сторонним продуктам без её одобрения пользоваться входом через claude.ai и лимитами подписки, так что редактор, работающий через этот хост на Pro или Max, ставит аккаунт под риск.

## Установка

Нужны Node 22 или новее и Claude Code, залогиненный в ваш аккаунт.

```bash
git clone https://github.com/GlebSmolyakov/claude-proxy.git
cd claude-proxy
pnpm install
pnpm run build
```

Бинарник Claude Code берётся тот, что приезжает вместе с SDK. Чтобы работал ваш установленный `claude`, задайте путь к нему в `CLAUDE_CODE_EXECUTABLE`.

## Подключить к редактору

В JetBrains Air: _панель задачи → выбор агента → Add ACP Agent_. Air откроет `acp.json`, на macOS это `~/Library/Application Support/JetBrains/Air/acp.json`. В Zed то же самое лежит в `settings.json` под ключом `agent_servers`.

```json
{
  "agent_servers": {
    "Claude Code": {
      "command": "node",
      "args": ["/Users/you/WebstormProjects/claude-proxy/dist/index.js"]
    }
  }
}
```

После сохранения агент появляется в списке и работает в открытом проекте.

## Как это работает

Редактор запускает `dist/index.js` как обычную программу и общается с ним по JSON-RPC через stdin и stdout. Поэтому в stdout не пишется ничего, кроме протокола: логи идут в stderr.

```
редактор ──stdio──▶ claude-proxy ──▶ Claude Code (Agent SDK)
    ▲                    │
    └── события сессии ◀──┘   карточки, текст, разрешения, файлы, терминал
```

### Один агент на сессию

На `session/new` заводится сессия: папка проекта, режим разрешений, модель. Процесс ещё не запускается. Его поднимает первый промпт, и дальше он живёт: следующие промпты дописываются в тот же поток ввода, а разговор, автокомпактизация и контекст остаются внутри CLI. Ход не платит за запуск процесса и перечитывание транскрипта.

Агент, которым не пользовались 30 минут, останавливается, а сессия остаётся. Следующий промпт поднимает нового и возобновляет разговор по id сессии; так же хост поступает, если процесс упал посреди работы. На `session/close` агент останавливается сразу, и его терминалы возвращаются редактору.

### Что редактор получает

Каждое сообщение SDK переводится в событие `session/update`:

| Что пришло от агента      | Что видно в редакторе                            |
| ------------------------- | ------------------------------------------------ |
| текст и размышления       | ответ по мере набора                             |
| начало вызова инструмента | карточка действия                                |
| его вход и результат      | заголовок, дифф правки, вывод, статус            |
| `TodoWrite` и задачи      | план списком                                     |
| счётчики токенов          | сколько занято в контексте и во что обошёлся ход |
| расход подписки           | сообщение, когда окно лимита перевалило порог    |

Карточка вызова открывается сразу, как только инструмент назван, и уточняется, когда приходит его полный вход: сначала «Edit», потом «Edit src/a.ts» с диффом.

### Что редактор отдаёт агенту

Здесь всё зависит от того, что редактор объявил про себя в `initialize`.

- **Файлы.** Есть `fs/read_text_file` и `fs/write_text_file` — встроенные `Read`, `Write` и `Edit` перенаправляются на них. Агент видит несохранённые правки, а его собственные ложатся в буфер.
- **Терминал.** Есть `terminal/create` — `Bash` запускается в терминале редактора, и этот терминал висит на карточке вызова, пока команда идёт.
- **Разрешения.** Всё, что не разрешено режимом сессии и вашими настройками, уходит диалогом: «Allow», «Always allow», если CLI предложил правило, и «Reject». Чтение внутри папок сессии проходит молча, как у встроенного `Read`.
- **Вопросы.** Есть формы — агент задаёт свои вопросы через `AskUserQuestion`, и туда же идут запросы ввода от MCP-серверов. Нет форм — вопросы выключены.
- **Вход.** Есть терминальная аутентификация — в списке способов входа появляется запуск `claude auth login`.

Чего редактор про себя не объявил, то остаётся за агентом: файлы идут на диск, команды выполняются молча, вопросы не задаются.

### Настройки сессии

Режим переключается через `session/set_mode`: `default`, `acceptEdits`, `plan`, `dontAsk`, `bypassPermissions`. Через `session/set_config_option` меняются модель, уровень усилий и размышления. Модель переключается у работающего агента на лету, а усилия и размышления задаются при старте, поэтому простаивающий агент для них останавливается и следующий промпт поднимает нового — разговор при этом не теряется.

Список моделей сначала состоит из алиасов, а после первого запуска заменяется тем, что есть у аккаунта. Тогда же редактор получает список слэш-команд CLI, включая ваши собственные; команда, набранная как промпт, выполняется и отвечает сообщением агента.

### Граница между редактором и CLI

Редактор и CLI друг о друге не знают. Редактор говорит по ACP с хостом, CLI работает как обычный CLI, и всё, что между ними, происходит здесь. Поэтому MCP-серверы, которые редактор передаёт в `session/new`, по умолчанию до CLI не доходят: иначе они встретились бы за спиной хоста, а stdio-сервер — это ещё и запуск программы, которую назвал редактор. Каждый такой сервер пишется в лог с его командой или адресом, а `--allow-mcp Air` или `--allow-mcp all` пропускает их дальше.

Если инструменты редактора всё же нужны, их берёт на себя хост: `--proxy-mcp Air` или `--proxy-mcp "Air:browser-read-page,browser-screenshot"` подключает сервер к хосту, а не к CLI. Выбранные инструменты агент видит как наши, под именами вида `Air: browser-read-page`, и каждый их вызов проходит через тот же диалог и ту же карточку, что и всё остальное.

Чтение без вопросов работает только в папках сессии, и папка должна быть достаточно узкой. Домашняя папка, корень файловой системы и всё, что над домашней, слишком широки: оттуда каждый файл идёт через диалог.

### Старые сессии

`session/list` перечисляет разговоры, которые CLI сохранил в папке проекта: их id, заголовок и время последней правки, по пятьдесят штук с курсором на остальное. `session/load` читает сохранённый CLI разговор и проигрывает его событиями: реплики пользователя, текст и размышления агента, карточка каждого вызова с результатом, план. После этого следующий промпт продолжает ту же сессию.

## Параметры

| Параметр            | По умолчанию           | Что задаёт                                                         |
| ------------------- | ---------------------- | ------------------------------------------------------------------ |
| `--permission-mode` | `default`              | Режим новых сессий                                                 |
| `--model`           | модель из настроек CLI | Модель всех сессий: алиас или полный id                            |
| `--idle-minutes`    | `30`                   | Через сколько остановить агента без работы; `0` оставляет его жить |
| `--login`           |                        | Отдать терминал входу Claude Code                                  |
| `LOG_LEVEL`         | `info`                 | С `debug` в лог попадает stderr CLI                                |

## Настройки проекта

Флаги задают поведение всему процессу, а редактор открывает в нём разные проекты. Файл `.claude-proxy.json` рядом с кодом сужает флаги для своей папки:

```json
{
  "model": "haiku",
  "permissionMode": "plan",
  "allowMcp": ["Air"],
  "proxyMcp": { "Air": ["browser-read-page"] }
}
```

Чего в файле нет, берётся из флагов, и просить файл может только меньше, чем они дают. Режим свободнее того, с которым запущен хост, отклоняется, и так же отклоняется сервер, которого не называли в `--allow-mcp` или `--proxy-mcp`: файл приезжает вместе с кодом, а клонировать репозиторий, это не то же самое, что решать, что его агенту можно. Поле, которое хост не понимает, пропускается со строкой в логе.

## Чего здесь нет

- У перенаправленного `Bash` нет оболочки, которая помнит `cd` между вызовами, а вывод фоновой команды остаётся только в терминале редактора.
- Сабагенты показывают свои вызовы инструментов, но не текст: в ACP 1.4 нет вложенного транскрипта, куда его положить.
- `url`-элицитация от MCP-сервера отклоняется: чтобы закончить её в браузере, нужен канал обратно, которого здесь нет.
- Fast mode в настройки сессии не вынесен, у `query()` нет опции под него.

## Разработка

```bash
pnpm test
pnpm run check
```

Редактор запускает собранный `dist/index.js`, так что после правок нужна пересборка и перезапуск агента в редакторе.

### Как устроены тесты

Большинство, это юнит-тесты рядом с модулем, который они проверяют. Два слоя шире:

- `editor-work.test.ts` проигрывает рабочий день целиком через протокол. Оба конца настоящие: с одной стороны редактор ACP с буферами, терминалами и диалогами, с другой собственные обработчики инструментов хоста, а сценарием записаны только решения модели, то есть то, что напечатал бы CLI. Половины лежат в `editor.test-support.ts` (редактор) и `agent.test-support.ts` (CLI, который спрашивает разрешение и запускает инструменты в том же порядке, что настоящий).
- `cli.e2e.test.ts` запускает собранную программу отдельным процессом и говорит с ней через stdin и stdout, так что флаги, обвязка stdio и завершение проверяются так, как их видит редактор. Если исходники новее `dist`, сборка повторяется сама.

```
src/
├── index.ts          разбор аргументов, бинарник CLI, приложение ACP на stdio
├── acp-agent.ts      методы сессии, разрешения, вопросы, жизнь агента
├── agent.ts          опции query() и поток ввода сессии
├── session.ts        состояние сессии и карточки вызовов
├── updates.ts        сообщения SDK → события session/update
├── tools.ts          заголовок, вид, дифф и результат карточки, план
├── editor-tools.ts   файлы и команды через редактор
├── terminal.ts       bash в терминале редактора
├── questions.ts      вопросы агента и MCP-серверов формой
├── config.ts         модель, усилия, размышления
├── permissions.ts    режимы сессии и варианты ответа в диалоге
├── prompt.ts         промпт ACP → сообщение для агента
├── models.ts         какие имена моделей принимает `--model`
└── log.ts            логи в stderr
```
